# 🎓 LabTop: Система мониторинга лабораторных работ

![status](https://img.shields.io/badge/status-released-success)
![platform](https://img.shields.io/badge/platform-Windows-blue)
![language](https://img.shields.io/badge/language-C%2B%2B%2FCLI-purple)
![storage](https://img.shields.io/badge/storage-JSON-orange)
![version](https://img.shields.io/badge/version-1.0-brightgreen)

**LabTop** — desktop-приложение для управления лабораторными работами, написанное на **C++/CLI + Windows Forms**.
Система автоматизирует контроль файлов лабораторных, отслеживает готовность работ, проверяет структуру директорий и хранит данные локально в JSON-файле.

Проект создавался как попытка решить реальную проблему студентов:

> “Где лежит лаба?”, “Что ещё не сделано?”, “Есть ли отчёт?”, “Какой дедлайн?”, “Что я вообще сдавал?”

---

# ✨ Основные возможности

## 📊 Централизованный учет лабораторных работ

Каждая лабораторная работа хранится как отдельная запись в `ListView` и содержит:

* уникальный ID
* название работы
* статус выполнения
* дедлайн
* комментарий
* список недостающих файлов
* путь к директории проекта

---

## 📂 Автоматическая проверка файлов

Система анализирует содержимое выбранной папки и проверяет наличие необходимых файлов.

Поддерживаются:

| Тип        | Расширение      |
| ---------- | --------------- |
| Код        | `.txt`          |
| Отчёт      | `.doc`, `.docx` |
| Блок-схема | `.drawio`       |
| IDEF0      | `.vpd`          |

Проверка выполняется автоматически:

* при запуске программы
* после добавления лабораторной
* при обновлении статуса

---

## 🎨 Цветовая индикация состояния

LabTop использует визуальную систему статусов:

| Цвет          | Значение                   |
| ------------- | -------------------------- |
| 🟢 LightGreen | Работа полностью готова    |
| 🟡 Yellow     | Не хватает файлов          |
| 🔴 Red        | Пропущен дедлайн / Ошибки  |

Это позволяет быстро находить проблемные лабораторные без ручной проверки.

---

## 💾 Локальное хранение данных

Все данные сохраняются в JSON-файл:

```json
{
  "items": [
    {
      "text":"1",
      "subitems":[
        "ОАИП",
        "done",
        "12.06.2026",
        "Сдать до пары"
      ]
    }
  ]
}
```

Используется ручная сериализация без сторонних библиотек.

# 🧠 Архитектура проекта

Проект разделён на несколько логических компонентов.

---

## 📦 Models.h

Содержит модель данных `LabItem`.

```cpp
ref class LabItem
```

Модель хранит:

* идентификатор
* название
* статус
* дедлайн
* комментарии
* путь
* логические флаги требований

Также используется enum `LabColumns`, который задаёт индексы колонок таблицы.

Это устраняет проблему “магических чисел”:

```cpp
item->SubItems[Task]
```

вместо:

```cpp
item->SubItems[5]
```

---

## ⚙️ LabService

Основной слой бизнес-логики.

### Основные задачи:

### 🔹 Конвертация UI → Model

Метод:

```cpp
FromListViewItem()
```

преобразует `ListViewItem` в объект `LabItem`.

---

### 🔹 Поиск файлов

Метод:

```cpp
GetFilesWithMultipleExtensions()
```

выполняет:

* проверку пути
* проверку существования директории
* поиск файлов по расширениям

---

### 🔹 Автоматическое обновление статуса

Метод:

```cpp
UpdateItemStatus()
```

анализирует:

* существует ли путь
* какие файлы требуются
* какие файлы отсутствуют

После анализа автоматически:

* меняется статус
* обновляется колонка “Что нужно сделать”
* изменяется цвет строки

Перед сохранением строки проходят обработку:

```cpp

```

Это предотвращает повреждение JSON-файла.

# 🔄 Логика работы программы

## При запуске приложения:

1. Настраивается интерфейс
2. Создаются колонки таблицы
3. Загружается JSON
4. Для каждой лабораторной:

   * проверяется путь
   * проверяются файлы
   * обновляется статус

---

## При добавлении лабораторной:

1. Открывается форма ввода
2. Проверяется корректность данных
3. Генерируется новый ID
4. Выполняется поиск файлов
5. Формируется список недостающих элементов
6. Добавляется запись в `ListView`
7. Выполняется сохранение в JSON

---

## При двойном клике по лабораторной:

Показывается подробная информация:

* статус
* дедлайн
* комментарий
* список недостающих файлов
* путь к директории

Пользователь может:

* пометить работу как сданную
* вернуть статус обратно
