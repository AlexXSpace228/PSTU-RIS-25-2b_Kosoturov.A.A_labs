# Лабораторная работа  
## Работа с динамическими структурами данных и хэш-таблицами

---

# 1. Описание и анализ задачи

В рамках выполнения работы была поставлена задача разработать программный комплекс для управления набором данных на основе динамического массива.

Массив предназначен для хранения не менее `100` записей, каждая из которых содержит базовую информацию о человеке:

- фамилию;
- имя;
- отчество;
- дату рождения;
- номер паспорта.

Для первичного заполнения структуры был задействован встроенный генератор псевдослучайных чисел (ДСЧ), выбирающий значения из заранее подготовленных списков имен, фамилий и дат.

---

## Основные возможности программы

Программа обеспечивает долгосрочное хранение информации благодаря реализованным механизмам сериализации:

- сохранение массива в текстовый файл;
- загрузка массива из файла обратно в память программы.

Дополнительно реализован функционал динамического изменения размера структуры, позволяющий:

- добавлять новые элементы;
- удалять существующие записи.

---

# 1.1 Аналитическая часть задачи

Главной аналитической задачей работы стала реализация алгоритма эффективного поиска записи по заданному ключу.

В качестве уникального идентификатора выбран номер паспорта.

Для организации поиска была спроектирована хэш-таблица.

Определение позиции элемента осуществляется с помощью хэш-функции деления с остатком:

:contentReference[oaicite:0]{index=0}

где:

- `k` — числовое представление ключа;
- `M` — размер таблицы.

---

## Обработка коллизий

В связи с возможностью возникновения коллизий была реализована открытая адресация.

При возникновении коллизии алгоритм выполняет линейное пробирование:

1. вычисляется индекс элемента;
2. проверяется занятость ячейки;
3. при занятости индекс увеличивается на единицу;
4. поиск продолжается до нахождения свободной позиции.

---

## Анализ эффективности

В программе реализован модуль аналитики, подсчитывающий количество коллизий при размещении массива в таблицах различного размера:

- `M = 40`
- `M = 75`
- `M = 90`

Это позволяет исследовать влияние размера таблицы на эффективность хэширования.

# 3.1 Результаты анализа коллизий

## Таблица размером `M = 40`

При размере таблицы существенно меньшем количества записей наблюдается максимальное число коллизий.

Причина:

- высокая плотность заполнения;
- частое возникновение конфликтов индексов;
- необходимость многократного линейного пробирования.

---

## Таблица размером `M = 75`

Количество коллизий уменьшается, однако остается достаточно высоким.

---

## Таблица размером `M = 90`

Плотность заполнения таблицы снижается.

Это приводит к:

- уменьшению количества коллизий;
- ускорению поиска;
- повышению эффективности хэширования.
