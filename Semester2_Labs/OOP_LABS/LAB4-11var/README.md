# Постановка задачи

1. Определить пользовательский класс.  
2. Определить в классе следующие конструкторы: без параметров, с параметрами, копирования.  
3. Определить в классе деструктор.  
4. Определить в классе компоненты-функции для просмотра и установки полей данных (селекторы и модификаторы).  
5. Перегрузить операцию присваивания.  
6. Перегрузить операции ввода и вывода объектов с помощью потоков.  
7. Определить производный класс.  
8. Написать программу, в которой продемонстрировать создание объектов и работу всех перегруженных операций.  
9. Реализовать функции, получающие и возвращающие объект базового класса. Продемонстрировать принцип подстановки.

# Описание классов и компонентных функций

Разработка началась с базового класса **TRIAD**, включающего три переменные типа int: first, second и third. Для обеспечения прямого доступа к этим полям из производного класса **TIME**, они были помещены в секцию protected, а не private. В классе TRIAD реализованы три вида конструкторов: без параметров (инициализирует поля нулями), с параметрами и конструктор копирования.  

Далее были прописаны селекторы (геттеры) и модификаторы (сеттеры) — функции, позволяющие читать и изменять значения полей извне. Для удобного приравнивания объектов друг к другу был перегружен оператор присваивания =, куда добавлена проверка на самоприсвоение (if (&T == this)), чтобы исключить лишние операции при выполнении конструкции вида t1 = t1. Также через дружественные функции были перегружены операторы << и >> для удобного вывода данных в консоль и ввода с клавиатуры.  

Методы plus_first_one(), plus_second_one() и plus_third_one() в базовом классе выполняют простое прибавление единицы к соответствующему полю. Они объявлены виртуальными (virtual), чтобы в производном классе существовала возможность переопределить их под новую логику.  

Затем был создан класс **TIME**, который открыто наследует **TRIAD**. В нем прописаны собственные конструкторы, вызывающие конструкторы базового класса, так как набор полей остался прежним. Основная логика класса TIME сосредоточена в переопределенных виртуальных методах plus_*. В них добавлена обработка переполнения: если секунды достигают значения 60, они сбрасываются в 0, а минуты увеличиваются на 1 (через вызов соответствующего метода для минут). Аналогичная цепочка вызовов работает вплоть до часов, которые сбрасываются при достижении 24. Дополнительно реализованы методы для увеличения времени сразу на заданное количество часов, минут или секунд — для корректных вычислений там применяется операция получения остатка от деления %. Оператор вывода для TIME был перегружен заново с использованием манипуляторов setfill и setw из библиотеки <iomanip>, что обеспечило формат вывода времени в виде 00:00:00.

# Определение глобальных функций и функция main()

Для проверки принципа подстановки были написаны глобальные функции printObject(TRIAD& t) и createDefault(). В функции main() проведено подробное тестирование каждого аспекта. Сначала создаются объекты базового класса, проверяются все конструкторы, работа геттеров и сеттеров, а также перегруженное присваивание. Затем тестируется работа виртуальных методов. После этого выполняется проверка класса TIME, где особое внимание уделяется работе механизма переполнения (переход через сутки) при добавлении секунд и минут.

# Объяснение результатов работы программы

Результаты вывода в консоль полностью подтверждают корректность реализованной логики. Особый интерес представляет демонстрация принципа подстановки. При передаче объекта класса TIME в функцию printObject, которая ожидает ссылку на базовый тип TRIAD, компилятор не выдает ошибок. Функция успешно принимает объект-наследник и корректно с ним работает. Аналогичная ситуация наблюдается с виртуальными функциями: благодаря механизму позднего связывания программа непосредственно во время выполнения определяет, чей именно метод plus_third_one() необходимо вызвать, ориентируясь на реальный тип объекта (на который указывает ссылка), а не на тип самой ссылки.

# Ответы на контрольные вопросы

Ниже представлены ответы на контрольные вопросы с акцентом на понимание того, как данные механизмы работают "под капотом".

1. **Для чего используется механизм наследования?**  
Этот механизм позволяет избежать дублирования кода. Можно взять уже готовый, отлаженный класс и на его базе сделать новый, добавив или изменив только необходимое. Это выстраивает четкую логическую иерархию (например, «Время — это частный случай тройки чисел»).

2. **Каким образом наследуются компоненты класса, описанные со спецификатором public?**  
Если наследование открытое (public), то всё открытое в базовом классе остается открытым в производном. Если защищенное (protected), то становится защищенным. Если закрытое (private), то закрытым.

3. **Каким образом наследуются компоненты класса, описанные со спецификатором private?**  
Они физически присутствуют в памяти производного объекта, но напрямую обратиться к ним из наследника нельзя. Доступ к ним можно получить только через открытые или защищенные методы базового класса.

4. **Каким образом наследуются компоненты класса, описанные со спецификатором protected?**  
Они доступны внутри самого класса и внутри всех его наследников. Извне (в main) к ним обратиться нельзя. При открытом наследовании они так и остаются protected в классе-наследнике.

5. **Каким образом описывается производный класс?**  
Через двоеточие после имени нового класса. Указывается спецификатор доступа и имя базового класса: `class Derived : public Base { ... };`

6. **Наследуются ли конструкторы?**  
Нет. Производный класс должен иметь свои конструкторы, но в списке их инициализации требуется вызывать конструкторы базового класса (иначе автоматически вызовется базовый конструктор по умолчанию).

7. **Наследуются ли деструкторы?**  
Также нет. У каждого класса в иерархии имеется свой деструктор.

8. **В каком порядке конструируются объекты производных классов?**  
Сначала закладывается "фундамент": вызывается конструктор базового класса. Только после этого выполняется код конструктора производного класса.

9. **В каком порядке уничтожаются объекты производных классов?**  
В строго обратном порядке. Сначала разрушается производный объект (вызывается его деструктор), а затем вызывается деструктор базового класса.

10. **Что представляют собой виртуальные функции и механизм позднего связывания?**  
Виртуальные функции — это методы, которые можно переопределить в классе-наследнике. Механизм позднего связывания означает, что программа решает, какой конкретно метод вызвать (базовый или переопределенный), не в момент компиляции, а непосредственно во время работы, анализируя реальный тип объекта, на который указывает указатель или ссылка.

11. **Могут ли быть виртуальными конструкторы? Деструкторы?**  
Конструкторы виртуальными быть не могут (на момент создания точно известно, какой именно объект строится). А вот деструкторы могут и должны быть виртуальными, если в классе есть хотя бы одна виртуальная функция. Если удалять объект наследника через указатель на базу, обычный деструктор не очистит память наследника, что приведет к утечке памяти.

12. **Наследуется ли спецификатор virtual?**  
Да. Если функция помечена как virtual в базовом классе, во всех её переопределениях в наследниках она тоже автоматически будет виртуальной (даже если не указывать само ключевое слово virtual, хотя для ясности кода принято писать спецификатор override).

13. **Какое отношение устанавливает между классами открытое наследование?**  
Отношение "является" (is-a). Студент является человеком. Время является тройкой чисел.

14. **Какое отношение устанавливает между классами закрытое наследование?**  
Отношение "реализовано посредством" (implemented-in-terms-of). Наследник использует базу для своей работы, но внешний код не имеет информации об этой связи.

15. **В чем заключается принцип подстановки?**  
Объект производного класса можно использовать везде, где синтаксис требует объект базового класса (например, передавать в качестве аргументов в функции или сохранять в массивы указателей на базу).

16. **Какие компонентные данные будет иметь объект х класса Teacher?**  
Исходя из того, что age и name объявлены в секции public класса Student, объект х будет содержать:  
• age (public)  
• name (public)  
• post (protected)  
• stage (protected)
