# Постановка задачи
1.	Создать пользовательский класс с минимальной функциональностью.
2.	Написать функцию для создания объектов пользовательского класса (ввод исходной информации с клавиатуры) и сохранения их в потоке (файле).
3.	Написать функцию для чтения и просмотра объектов из потока.
4.	Написать функцию для удаления объектов из потока в соответствии с заданием варианта. Для выполнения задания выполнить перегрузку необходимых операций.
5.	Написать функцию для добавления объектов в поток в соответствии с заданием варианта. Для выполнения задания выполнить перегрузку необходимых операций.
6.	Написать функцию для изменения объектов в потоке в соответствии с заданием варианта. Для выполнения задания выполнить перегрузку необходимых операций.
7.	Для вызова функций в основной программе предусмотреть меню.

Согласно требованиям индивидуального варианта №11, требовалось спроектировать пользовательский класс Money, предназначенный для работы с денежными суммами. Сумма должна представляться двумя полями: рубли (тип long) и копейки (тип int). Программный комплекс должен поддерживать: 
•	Удаление всех записей, значение которых превышает заданное пользователем. 
•	Уменьшение в два раза всех записей, точно совпадающих с заданным значением. 
•	Добавление заданного количества (K) новых записей непосредственно после элемента с указанным порядковым номером. 

## 1.1. Описание пользовательского класса
Для решения поставленной задачи был разработан класс Money. В его закрытой (private) части инкапсулированы два поля: rub для хранения количества рублей и kop для учета копеек. Дополнительно в классе реализован вспомогательный закрытый метод normalize(). Его функциональная роль заключается в автоматическом переводе избыточных копеек в рубли (например, преобразование 150 копеек в 1 рубль 50 копеек), а также в корректной обработке отрицательных значений копеек при математических операциях. Класс оснащен набором конструкторов (по умолчанию, с параметрами, конструктор копирования) и деструктором для обеспечения корректного жизненного цикла объектов.

## 1.2. Перегруженные операции пользовательского класса
С целью обеспечения удобного и интуитивно понятного взаимодействия с объектами класса Money был выполнен ряд перегрузок стандартных операций языка C++:
•	Оператор присваивания (=): обеспечивает корректное копирование значений полей из одного объекта в другой.
•	Операции сравнения (<, >, ==): позволяют логически сопоставлять две денежные суммы. Перегрузка оператора строгого равенства (==) была необходима для реализации алгоритма поиска и изменения заданного значения. 
•	Инкремент (++): перегружен в префиксной и постфиксной формах для добавления одной копейки к текущей сумме. 
•	Оператор деления (/): перегружен для деления денежной суммы на целое число, что напрямую отвечает требованию варианта об уменьшении суммы в два раза.
•	Операции потокового ввода/вывода (<<, >>): перегружены как дружественные функции (friend) в двух вариациях. Первая пара работает со стандартными потоками istream/ostream для интерактивного общения с пользователем через консоль (вывод реализован с отделением дробной части запятой ). Вторая пара адаптирована под файловые потоки fstream для обеспечения бесшовного сохранения и чтения объектов из дисковой памяти. 

## 1.3. Определение функций для работы с файлом
Управление файловыми данными было вынесено в отдельный заголовочный файл file_work.h. В нем реализованы следующие функции:
•	Создание файла (make_file): Функция инициализирует файловый поток в режиме записи с предварительной очисткой содержимого (ios::out | ios::trunc). Студент организовал циклический ввод атрибутов объекта с клавиатуры с последующей их отправкой в файловый поток. 
•	Вывод файла (print_file): Осуществляет открытие потока для чтения. Данные считываются из файла в объекты класса Money до достижения конца файла, после чего форматированно выводятся на экран монитора. 
•	Удаление записей (del_file): Алгоритм построен на использовании вспомогательного файла. Исходный файл открывается для чтения, а временный — для записи. Записи последовательно считываются. Если текущая запись не превышает заданного критерия (не попадает под условие удаления), она сохраняется во временный файл. В завершении исходный файл удаляется функцией remove(), а временный переименовывается в исходный функцией rename(). 
•	Изменение записей (change_file): Применяется аналогичный подход с временным файлом. При обнаружении элемента, равного искомому, программа уменьшает его значение в два раза (с помощью перегруженного оператора деления) и записывает обновленный вариант во временный поток. Остальные записи переносятся без модификаций. 
•	Добавление записей (add_file): Функция переносит данные из старого файла в новый. В момент, когда внутренний счетчик считанных записей достигает заданного пользователем номера (индекса), программа приостанавливает копирование и запрашивает у пользователя ввод K новых элементов, которые немедленно помещаются во временный файл. После этого перенос оставшихся оригинальных записей продолжается. 

## 1.4. Функция main()
Функция main() выступает в роли главного контроллера приложения. В ней организовано интерактивное консольное меню, реализованное через цикл do-while в связке с оператором switch. Пользователь получает возможность циклически выбирать требуемые действия: от создания нового набора данных до выполнения сложных модификаций (удаление, изменение, добавление). В функции предусмотрена обработка потенциальных ошибок, таких как невозможность открытия файла, с последующим уведомлением пользователя. 

## 1.5. Объяснение результатов работы программы
Разработанный программный комплекс полностью удовлетворяет условиям задачи. При тестировании программа успешно переводит избыточные копейки в рубли (благодаря методу normalize), корректно форматирует вывод (например, 5 рублей 5 копеек выводится как 5,05). Алгоритмы работы с файловой системой демонстрируют стабильность: использование временного файла temp.txt позволяет без риска потери данных проводить фильтрацию (удаление), модификацию (деление на два) и расширение (вставка элементов в середину) наборов данных, хранящихся на диске.

# 2. Ответы на контрольные вопросы
1.	Что такое поток? Поток определяется как последовательность байтов, которая не зависит от конкретного устройства, с которым производится обмен информацией (будь то оперативная память, дисковый файл, клавиатура или принтер). 
2.	Какие типы потоков существуют? Потоки классифицируются на стандартные (связанные с клавиатурой и экраном), строковые и файловые. 
3.	Какую библиотеку надо подключить при использовании стандартных потоков? Для работы со стандартными потоками необходимо задать директиву #include <iostream>. 
4.	Какую библиотеку надо подключить при использовании файловых потоков? Использование файловых потоков требует подключения заголовочного файла #include <fstream>. 
5.	Какую библиотеку надо подключить при использовании строковых потоков? Для доступа к функционалу строковых потоков подключается библиотека #include <sstream>. 
6.	Какая операция используется при выводе в форматированный поток? Как правило, при выводе применяется перегруженная операция сдвига влево <<. 
7.	Какая операция используется при вводе из форматированных потоков? Ввод данных осуществляется с помощью перегруженной операции сдвига вправо >>. 
8.	Какие методы используются при выводе в форматированный поток? Для вывода символов в поток можно использовать методы put() и write(). 
9.	Какие методы используется при вводе из форматированного потока? Для помещения символов или строк в переменные применяются методы get(), read(), а также метод getline(). 
10.	Какие режимы для открытия файловых потоков существуют? Существуют следующие режимы: in (чтение), out (запись), trunk (удаление старого содержимого), app (запись в конец), ate (переход в конец файла) и binary (двоичный режим). 
11.	Какой режим используется для добавления записей в файл? Для открытия потока с целью записи данных в конец файла используется режим app. 
12.	Какой режим (комбинация режимов) используется в конструкторе ifstream file(“f.txt”)? В данном классе по умолчанию используется режим in (открытие потока для чтения). 
13.	Какой режим (комбинация режимов) используется в конструкторе fstream file(“f.txt”)? Двунаправленный файловый поток fstream требует явного указания режимов, но в стандартной практике для обеспечения чтения и записи используется комбинация in | out. 
14.	Какой режим (комбинация режимов) используется в конструкторе ofstream file(“f.txt”)? Для выходного потока по умолчанию применяется режим out. 
15.	Каким образом открывается поток в режиме ios::out|ios::app? Такая комбинация обеспечивает дозапись данных в конец файла; при этом, если указанного файла не существует на диске, он автоматически создается. 
16.	Каким образом открывается поток в режиме ios::out |ios::trunc? Этот режим выполняет стирание старого содержимого файла и подготовку к новой записи; в случае отсутствия файла происходит его создание. 
17.	Каким образом открывается поток в режиме ios::out |ios::in|ios::trunk? Данная конфигурация открывает поток одновременно для чтения и записи, предварительно стирая старые данные; несуществующий файл будет создан. 
18.	Каким образом можно открыть файл для чтения? Файл можно открыть, создав объект класса входного потока ifstream stream("c:/files/number.txt"); или воспользовавшись методом open(). 
19.	Каким образом можно открыть файл для записи? Открытие для записи реализуется через объявление переменной выходного потока, например, ofstream stream("d:/files/number.txt");. 
20.	Привести примеры открытия файловых потоков в различных режимах. Пример для обычной записи: ofstream stream("d:/files/number.txt");. Пример для дозаписи в конец: ofstream stream("d:/files/number.txt", std::ios::app);. 
21.	Привести примеры чтения объектов из потока. Чтение объектов может выполняться в цикле: while(stream>>p) { ... } или при посимвольном чтении while(stream.get(c)) { ... }. 
22.	Привести примеры записи объектов в поток. Запись реализована с помощью оператора вывода: stream<<p<<"\n";. 
23.	Сформулировать алгоритм удаления записей из файла. Открываются исходный файл для чтения и временный файл для записи. Организуется цикл чтения объектов до признака конца файла. Если текущий объект не удовлетворяет условию удаления, он записывается во временный файл. После завершения цикла оба потока закрываются. Исходный файл удаляется с диска, а временный переименовывается в исходный. 
24.	Сформулировать алгоритм добавления записей в файл. Для добавления в середину файла открываются исходный и временный потоки. Данные считываются из исходного файла и копируются во временный. При достижении требуемой позиции во временный файл вставляются новые записи. По завершении переписывания файлов исходный удаляется, а временный переименовывается. Для добавления строго в конец достаточно открыть поток в режиме ios::app и дописать новые данные. 
25.	Сформулировать алгоритм изменения записей в файле. Алгоритм аналогичен удалению: создается временный файл. В цикле происходит чтение оригинальных объектов. Если объект соответствует критериям изменения, в консоли может запрашиваться подтверждение , после чего во временный файл пишется его измененная версия. В противном случае во временный поток дублируется неизмененный оригинал. Завершается процедура закрытием потоков, удалением старого файла и переименованием временного.
