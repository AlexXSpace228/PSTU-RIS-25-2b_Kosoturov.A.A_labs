# Постановка задачи

1. Определить пользовательский класс.  
2. Определить в классе следующие конструкторы: без параметров, с параметрами, копирования.  
3. Определить в классе деструктор.  
4. Определить в классе компоненты-функции для просмотра и установки полей данных (селекторы и модификаторы).  
5. Перегрузить операцию присваивания.  
6. Перегрузить операции ввода и вывода объектов с помощью потоков.  
7. Перегрузить операции указанные в варианте.  
8. Написать программу, в которой продемонстрировать создание объектов и работу всех перегруженных операций.  

---

# Описание класса Money

Класс содержит два поля данных:

a. long roubles — для хранения целой части суммы.  
b. int peny — для хранения копеек.  

Объекты класса обеспечивают корректное хранение денежных значений, где копейки всегда находятся в диапазоне [0, 99].

---

# Определение компонентных функций

В классе реализованы следующие методы:

a. Конструкторы: инициализируют поля начальными значениями.  

b. Селекторы (GetRUB, GetP): возвращают значения полей (помечены const для корректной работы с константными объектами).  

c. Модификаторы (setRoubles, setPeny): устанавливают новые значения полей с простейшей проверкой на отрицательные значения копеек.  

d. Оператор =: выполняет поэлементное копирование данных, защищен от самоприсваивания.  

e. Инкремент (++): увеличивает значение копеек на 1. При достижении 100 копеек происходит увеличение рубля и обнуление копеек.

---

# Определение глобальных функций

Для обеспечения интуитивно понятного синтаксиса std::cin >> m и std::cout << m были определены дружественные (friend) функции:

• operator>>: организует диалог с пользователем для ввода данных.  
• operator<<: выводит сумму в формате рубли,копейки (с корректным отображением ведущего нуля для копеек меньше 10).

---

# Объяснение результатов работы программы

1. Создание: m1 инициализируется нулями, m2 получает 100.50, m3 копирует m2.  
2. Модификация: С помощью сеттеров m1 меняет значение на 200.75.  
3. Ввод: Программа ожидает от пользователя ввод (например, 50 20), который сохранится в m4.  
4. Инкремент: Демонстрируется разница: префиксный изменяет объект сразу, постфиксный возвращает временную копию до изменения.  
5. Сравнение: Логика переводит сумму в общее количество копеек для корректного сравнения объектов.

# Ответы на контрольные вопросы

1. Для чего используются дружественные функции?  
Для доступа к закрытым (private) и защищенным (protected) членам класса извне, не являясь при этом методами самого класса.

2. Правила и особенности:  
Объявляются внутри класса с ключевым словом friend. Не имеют указателя this. На них не влияют спецификаторы public/private.

3. Перегрузка унарных операций:  
Либо как метод класса без аргументов, либо как глобальная функция с одним аргументом (объектом класса).

4. Унарная внутри класса:  
0 дополнительных операндов (используется текущий this).

5. Унарная вне класса:  
1 операнд (сам объект).

6. Бинарная внутри класса:  
1 операнд (правый), левым является this.

7. Бинарная вне класса:  
2 операнда (левый и правый).

8. Префикс vs Постфикс:  
Постфиксная функция имеет фиктивный параметр типа int, чтобы компилятор мог их отличить.

9. Перегрузка присваивания:  
Только как метод класса. Рекомендуется проверять на самоприсваивание (if (this == &other)).

10. Что возвращает присваивание?  
Ссылку на текущий объект (*this), чтобы была возможность строить цепочки типа a = b = c.

11. Перегрузка ввода-вывода:  
Только как дружественные (глобальные) функции, так как левым операндом является поток (ostream& или istream&), а не наш класс.

12. ++s (метод):  
Компилятор вызовет s.operator++().

13. ++s (friend):  
Компилятор вызовет operator++(s).

14. a < b (метод):  
Компилятор вызовет a.operator<(b).

15. a > b (friend):  
Компилятор вызовет operator>(a, b).
